# future-scholars-website

Website for Future Scholars Montessori Academy (Ottawa). Monorepo (npm workspaces) of a Next.js frontend + Sanity Studio: page builder, Visual Editing via Presentation Tool, Live Content API. Plan and locked decisions: [docs/FSMA-BUILD-PLAN.md](docs/FSMA-BUILD-PLAN.md).

## Stack

- **Next.js 16** App Router with **Cache Components** (`cacheComponents: true` — see [docs/CACHING.md](docs/CACHING.md)), React 19, TypeScript 6 (strict).
- **Sanity v6** (Studio) + `next-sanity` v13 + `@sanity/client` v7. Sanity Functions via Blueprints (`sanity.blueprint.ts` + `functions/`).
- **Tailwind CSS v4** (CSS-first config via `@theme` in `globals.css`).
- **Runtime/PM:** repo ships with `npm` workspaces and a `package-lock.json`. Use `npm run …` for parity with the workspace scripts; do **not** introduce Bun/pnpm lockfiles here.
- **Plugins:** `@sanity/assist`, `sanity-plugin-media`, `sanity-plugin-asset-source-unsplash` (placeholder mastheads until real photography), Presentation Tool.

## Commands

Run from repo root unless noted:

- `npm run dev` — runs TypeGen once (root `predev`), then Next (`:3000`) and Studio (`:3333`) in parallel.
- `npm run lint` — ESLint on frontend.
- `npm run type-check` — `tsc --noEmit` in both workspaces.
- `npm run format` — Prettier (`@sanity/prettier-config`).
- Frontend build: `npm run build --workspace=frontend` (extracts the schema and runs TypeGen first via `prebuild`).
- Studio deploy: `npm --workspace=studio run deploy`.
- Functions deploy: `npx sanity blueprints deploy` from repo root (logs: `npx sanity functions logs invalidate-tags`; local playground: `npx sanity functions dev`). One-time setup in [docs/CACHING.md](docs/CACHING.md).

**TypeGen is a root-level concern** — both workspaces read the single `sanity.schema.json` at the repo root, so it is owned by the root `package.json`, never by a workspace `predev`. Root `npm run dev` runs `predev` → `npm run typegen`, which extracts the schema once (from `studio/`) and then generates `frontend/sanity.types.ts` and `studio/sanity.types.ts` in parallel, before either dev server starts.

- `npm run typegen` (root) — extract + generate for both workspaces. Use this when `sanity.types.ts` or `sanity.schema.json` drift.
- `npm run schema:extract` (root) — extract only. Always passes `--force`; `sanity schema extract` prompts to overwrite without it, which deadlocks a parallel dev run.
- Do **not** add `predev`/`prebuild` TypeGen hooks to `frontend/` or `studio/`. Two workspaces racing to write the same `sanity.schema.json` produces torn reads and duplicated prompts.

## Sanity content model

Documents: `page`, `program` (Infants / Toddlers / Casa), `testimonial`, `person` (staff; `role`, `bio`, `credentials`, `order`). Singleton: `settings` (`_id: "settings"`: title, description, blurb, `contact` — the only source of contact data (D16), `schoolInfo` JSON-LD fields, navigation, legal, homepage, ogImage).

`page` fields: `name`, `slug`, `heading`/`subheading`/`titleDisplay`, `masthead` (page field, not a block — D12; owns the visual `<h1>`), `seo`, and a `pageBuilder` rendered by `app/components/blocks/PageBuilder.tsx` → `blocks/BlockRenderer.tsx`.

Page-builder blocks: `callToAction`, `infoSection`, `featuresGrid` (school icon set), `stats` ("Key facts"), `testimonials` (reads testimonial documents; cards or letters layout), `programsGrid`, `facultyGrid`, `contactDetails`, `gallery` (+ `galleryImage`/`galleryVideo`), `faq`, `note`, `pullQuote` (`repeatsText` → `aria-hidden`). Every block takes an optional `anchor` (rendered as the wrapper `id`, e.g. `/about#admissions`); internal `link`s can target it via their `anchor` field, validated against the target document's block anchors. Objects: `masthead`, `seo`, `contact`, `social`, `navLink`, `navDropdown`, `button`, `link` (URL, or page/program reference + optional section anchor), `blockContent`, `blockContentTextOnly`.

Routing (mirror in Studio's Presentation `mainDocuments` + `locations` and `resolveHref`):
- `/` → the `page` that `settings.homepage` points at (its own slug 301s to `/`)
- `/:slug` → `page` (Programs, Montessori, Testimonials, Gallery, About are all `page` documents)
- `/programs/:slug` → `program` detail (D17: the `/programs` index is a CMS page; only the dynamic segment is coded)
- Legacy `.htm` URLs 301 in `frontend/next.config.ts` (D3).

## Queries / data fetching

**Read [docs/CACHING.md](docs/CACHING.md) before any data-fetching work** — Cache Components is enabled and every fetch follows the three-layer pattern.

- All queries live in `frontend/sanity/lib/queries.ts`, wrapped in `defineQuery` so TypeGen can type results.
- Fetch via `sanityFetch` from `@/sanity/lib/live` (RSC). It returns `{data}` — destructure. `defineLive` is `strict: true`: every call MUST pass `perspective` + `stega`, and the calling async function MUST carry `'use cache'`. Never hardcode `perspective: 'published'` / `stega: false` in page-content components — resolve via `getDynamicFetchOptions()` outside the cache boundary and pass as props (three-layer pattern).
- Helper routing: `sanityFetchStaticParams` in `generateStaticParams`; `sanityFetchMetadata` in `generateMetadata` / `sitemap.ts` / `manifest.ts` / JSON-LD; `getSettings` (`@/app/components/layout`) for the settings singleton; `CachedPage` (`@/app/components/blocks`) renders a `page` document (shared by `/` and `/[slug]`) and 404s unknown slugs.
- The `<SanityLive>` component in `app/layout.tsx` is required for live updates — never remove it. It renders with `includeDrafts` + production-only `waitFor="function"` (backed by the `invalidate-tags` Sanity Function + `/api/revalidate-tags`).
- Client: `useCdn: true`, default `perspective: 'published'`, stega studioUrl. Server token comes from `SANITY_API_READ_TOKEN` via `sanity/lib/token.ts`.

## Conventions

- Server Components by default. Client components are explicit (`'use client'`) and small (`PageBuilder`, `SideNavLinks`, `SideNavMobile`, gallery lightbox, `DraftModeToast`).
- Visual Editing: wrap editable regions in `data-sanity={dataAttr({id, type, path}).toString()}`. The `PageBuilder` already does this for the array and each block via `pageBuilder[_key=="..."]`.
- Optimistic edits use `useOptimistic` from `next-sanity/hooks` — keep block reconciliation by `_key` (see `PageBuilder.tsx`).
- Components live in `frontend/app/components/`, grouped by domain with a barrel `index.ts` per folder (`blocks/` incl. `blocks/gallery/`, `layout/`, `motion/`, `portable-text/`, `visual-editing/`, `common/`, `seo/`, `icons/`). Import across folders via the barrel (`import {Masthead} from '@/app/components/layout'`); within a folder use relative paths (`./Masthead`). A new pageBuilder block goes in `blocks/`; a multi-file feature gets its own subfolder + barrel.
- Images: use `@/app/components/common` (`SanityImage`, built on `sanity-image`). `next.config.ts` allows `cdn.sanity.io` for `next/image` cases.
- Portable Text: render via `@/app/components/portable-text` (`PortableText`) or `@portabletext/react` directly for short fields. Strip stega before plain-text use (`toPlainText`).
- **Stega discipline:** any CMS string used in *logic* — object lookups (`tones[tone]`, `icons[icon]`), `===`/`switch` comparisons, `href`/`id` values, URL parsing — MUST go through `stegaClean` (from `@sanity/client/stega`) first. In draft mode these values carry invisible stega characters; raw use misses lookups or crashes the draft render (which loops Presentation Tool). Only `_`-prefixed fields (`_type`, `_key`, `_id`), numbers, and booleans are safe raw. Values only *displayed* should stay un-cleaned so click-to-edit overlays keep working.
- Styling: Tailwind v4 — colors/tokens are HSL channel triplets in `:root`, mapped in `@theme inline` inside `app/globals.css` (the source of truth; no `tailwind.config.ts`). Light theme only (D14) — no `dark:` variants. Fonts: Inter (body), Outfit (headings). shadcn components live in `frontend/components/ui/`. Use the `container` utility defined in `globals.css`.
- Path alias `@/*` → `frontend/*`.
- View transitions: React `<ViewTransition>` is enabled (`experimental.viewTransition`). **Always consider transitions when building UI** — see [docs/TRANSITIONS.md](docs/TRANSITIONS.md). App-wide crossfade + directional slides live in `app/components/motion/PageTransition.tsx` (wrapped around `{children}` in `layout.tsx`); tag navigations with `<Link transitionTypes={['nav-forward'|'nav-back']}>`, give fixed chrome a `viewTransitionName` (`site-rail`, `site-topbar`, `contact-hub`). Keep these RSC; CSS classes live in the view-transition block of `app/globals.css`.
- TS: strict; the workspace targets `esnext` with `module: preserve`. Don't add `any` to schema-derived types — extend the types in `sanity/lib/types.ts` instead.

## Visual Editing / Draft Mode

- Studio's Presentation Tool points at `SANITY_STUDIO_PREVIEW_URL` (default `http://localhost:3000`), enable route `/api/draft-mode/enable`.
- Draft mode is toggled by `app/api/draft-mode/enable/route.ts` (uses `defineEnableDraftMode`) and disabled by the server action in `app/actions.ts`.
- The `<VisualEditing/>` component only renders when `draftMode().isEnabled` is true.

## Gotchas

- `AGENTS.md` rule: read `node_modules/next/dist/docs/` before doing Next.js work — training data is older than v16.
- Never edit `frontend/sanity.types.ts` or `sanity.schema.json`; rerun TypeGen.
- After adding/changing a schema, re-run TypeGen *before* writing queries that reference new fields, otherwise `defineQuery` results will be typed `unknown`.
- New `pageBuilder` block type needs three changes: schema (`studio/src/schemaTypes/objects/...`), GROQ projection in `getPageQuery`, and a renderer in `app/components/blocks/` registered in `BlockRenderer.Blocks` (+ exported from `blocks/index.ts`).
- New routable document type needs: Presentation `mainDocuments` + `locations` entry (`studio/sanity.config.ts`), Next route, `documentHref` case in `frontend/sanity/lib/utils.ts` (drives links + sitemap; add the type to the `sitemapData` query), `resolveHref` update in `sanity.config.ts`, and — if editors should link to it — `linkableTypes` in `studio/src/schemaTypes/objects/link.ts`.
- Metadata/static-params fetches go through `sanityFetchMetadata` / `sanityFetchStaticParams` (never stega — encoded markers would leak into titles and URLs).
- Cache Components rules: no `cookies()`/`headers()`/awaited `params` inside `'use cache'`; `draftMode()` is the ONE dynamic API a top-level page/layout may await while staying in the static shell. Draft mode bypasses ALL `'use cache'` boundaries, so every fetching component reachable in draft mode — even one pinned to `perspective: 'published'`, e.g. `SiteJsonLd` — must render inside `<Suspense>`. Test `next dev` with draft mode both ON and OFF — the modes render through different layers.
- Only one sync-tag-invalidate function per dataset; the function must always call `done()` or `waitFor="function"` clients stop receiving live events (see docs/CACHING.md).
- `useCdn: true` + Live: Live still subscribes via the listener; CDN only affects the initial fetch.
- shadcn components live in `frontend/components/ui/` (alert, avatar, badge, button, card, carousel, collapsible, dialog, separator, sheet, skeleton, sonner). Icon library is Heroicons (configured in `components.json`); lucide is not installed.
- Empty `generateStaticParams` fails the build under Cache Components — return a `__placeholder__` slug (see `app/programs/[slug]`).
- Deploy the schema only with the Studio CLI (`cd studio && npx sanity schema deploy`), never the Sanity MCP `deploy_schema` tool (it creates a competing schema record).

## Accessibility

Read **[docs/A11Y.md](docs/A11Y.md) before touching UI** — it's the source of truth for color/contrast tokens, focus rules, ARIA conventions, image alt handling, and the per-PR checklist. Target is WCAG 2.2 AAA where feasible, AA floor. Use the `design:accessibility-review` skill on non-trivial visual changes; run Lighthouse Accessibility ≥95 before merging.

## Priorities (user preferences, applied here)

Performance-first, low CLS, minimal client JS — keep work in RSC, only opt into `'use client'` for hooks or Visual Editing. Target WCAG AAA where feasible — see [docs/A11Y.md](docs/A11Y.md). Avoid heavy deps. No WebGL (D15), no service worker.
