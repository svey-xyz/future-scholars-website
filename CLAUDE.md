# sanity-next-clean

Monorepo (npm workspaces) of a Next.js frontend + Sanity Studio. Real-time Visual Editing via Presentation Tool, Live Content API, page builder.

## Stack

- **Next.js 16** App Router, React 19, TypeScript 5.9 (strict).
- **Sanity v5** (Studio) + `next-sanity` v12 + `@sanity/client` v7.
- **Tailwind CSS v4** (CSS-first config via `@theme` in `globals.css`).
- **Runtime/PM:** repo ships with `npm` workspaces and a `package-lock.json`. Use `npm run …` for parity with the workspace scripts; do **not** introduce Bun/pnpm lockfiles here.
- **Plugins:** `@sanity/assist`, `sanity-plugin-asset-source-unsplash`, `@sanity/vision`, Presentation Tool.

## Layout

```
/                       npm workspaces root
├── frontend/           Next.js app
│   ├── app/            App Router routes + components
│   ├── sanity/lib/     client, live, queries, api, token, utils, types
│   ├── sanity.types.ts generated by TypeGen — DO NOT edit
│   └── tailwind.config.ts  legacy file; real theme lives in app/globals.css
├── studio/             Sanity Studio
│   └── src/schemaTypes/{documents,objects,singletons}/
├── sanity.schema.json  generated by `sanity schema extract` — DO NOT edit
└── AGENTS.md           "read Next docs from node_modules first"
```

## Commands

Run from repo root unless noted:

- `npm run dev` — runs Next (`:3000`) and Studio (`:3333`) in parallel.
- `npm run lint` — ESLint on frontend.
- `npm run type-check` — `tsc --noEmit` in both workspaces.
- `npm run format` — Prettier (`@sanity/prettier-config`).
- `npm run import-sample-data` — imports `studio/sample-data.tar.gz` into the `production` dataset.
- Frontend build: `npm run build --workspace=frontend` (runs `sanity typegen generate` first via `prebuild`).
- Studio deploy: `npm --workspace=studio run deploy`.

**TypeGen** runs automatically on `predev`/`prebuild`. If `sanity.types.ts` or `sanity.schema.json` drift, regenerate with `npm run sanity:typegen --workspace=frontend` (extracts schema from `studio/`, writes types into `frontend/`).

## Sanity content model

Documents: `page`, `post`, `person`. Singleton: `settings` (id `siteSettings`). Objects: `callToAction`, `infoSection`, `button`, `link`, `blockContent`, `blockContentTextOnly`. The `page` document has a `pageBuilder` array (`callToAction` | `infoSection`) rendered by `app/components/PageBuilder.tsx` → `BlockRenderer.tsx`.

Routing (mirror in Studio's Presentation `mainDocuments` + Next routes):
- `/` → `settings`
- `/:slug` → `page`
- `/posts/:slug` → `post`

## Queries / data fetching

- All queries live in `frontend/sanity/lib/queries.ts`, wrapped in `defineQuery` so TypeGen can type results.
- Fetch via `sanityFetch` from `@/sanity/lib/live` (RSC). It returns `{data}` — destructure. For `generateStaticParams` and metadata, pass `perspective: 'published'` and `stega: false`.
- The `<SanityLive>` component in `app/layout.tsx` is required for live updates — never remove it.
- Client: `useCdn: true` with stega studioUrl. Server token comes from `SANITY_API_READ_TOKEN` via `sanity/lib/token.ts`.

## Conventions

- Server Components by default. Client components are explicit (`'use client'`) and small (`PageBuilder`, `DraftModeToast`, etc.).
- Visual Editing: wrap editable regions in `data-sanity={dataAttr({id, type, path}).toString()}`. The `PageBuilder` already does this for the array and each block via `pageBuilder[_key=="..."]`.
- Optimistic edits use `useOptimistic` from `next-sanity/hooks` — keep block reconciliation by `_key` (see `PageBuilder.tsx`).
- Images: use `@/app/components/SanityImage` (built on `sanity-image`). `next.config.ts` allows `cdn.sanity.io` for `next/image` cases.
- Portable Text: render via `@/app/components/PortableText` (posts) or `@portabletext/react` directly for short fields. Strip stega before plain-text use (`toPlainText`).
- Styling: Tailwind v4 — colors/tokens are declared in `@theme` inside `app/globals.css`. The `tailwind.config.ts` is leftover and **not** the source of truth for v4 theme; prefer editing `globals.css`. Use the `container` utility defined there.
- Path alias `@/*` → `frontend/*`.
- TS: strict; the workspace targets `esnext` with `module: preserve`. Don't add `any` to schema-derived types — extend the types in `sanity/lib/types.ts` instead.

## Visual Editing / Draft Mode

- Studio's Presentation Tool points at `SANITY_STUDIO_PREVIEW_URL` (default `http://localhost:3000`), enable route `/api/draft-mode/enable`.
- Draft mode is toggled by `app/api/draft-mode/enable/route.ts` (uses `defineEnableDraftMode`) and disabled by the server action in `app/actions.ts`.
- The `<VisualEditing/>` component only renders when `draftMode().isEnabled` is true.

## Gotchas

- `AGENTS.md` rule: read `node_modules/next/dist/docs/` before doing Next.js work — training data is older than v16.
- Never edit `frontend/sanity.types.ts` or `sanity.schema.json`; rerun TypeGen.
- After adding/changing a schema, re-run TypeGen *before* writing queries that reference new fields, otherwise `defineQuery` results will be typed `unknown`.
- New `pageBuilder` block type needs three changes: schema (`studio/src/schemaTypes/objects/...`), GROQ projection in `getPageQuery`, and a renderer registered in `BlockRenderer.Blocks`.
- New routable document type needs: Presentation `mainDocuments` + `locations` entry (`studio/sanity.config.ts`), Next route, sitemap branch in `app/sitemap.ts`, and `resolveHref` update in `sanity.config.ts`.
- Metadata/static-params fetches must pass `stega: false` to avoid encoded markers leaking into titles and URLs.
- `useCdn: true` + Live: Live still subscribes via the listener; CDN only affects the initial fetch.
- shadcn MCP is wired in `.mcp.json`, but no shadcn components are installed yet — components live under `app/components/` as hand-rolled Tailwind. Check before assuming `@/components/ui/...` exists.

## Priorities (user preferences, applied here)

Performance-first, low CLS, minimal client JS — keep work in RSC, only opt into `'use client'` for hooks or Visual Editing. Target WCAG AAA where feasible. Avoid heavy deps. Prefer streaming/`<Suspense>` for post lists (already used on `/` and `/posts/[slug]`).
