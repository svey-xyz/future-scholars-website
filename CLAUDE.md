# sanity-next-clean

Monorepo (npm workspaces) of a Next.js frontend + Sanity Studio. Real-time Visual Editing via Presentation Tool, Live Content API, page builder.

## Stack

- **Next.js 16** App Router, React 19, TypeScript 5.9 (strict).
- **Sanity v5** (Studio) + `next-sanity` v12 + `@sanity/client` v7.
- **Tailwind CSS v4** (CSS-first config via `@theme` in `globals.css`).
- **Runtime/PM:** repo ships with `npm` workspaces and a `package-lock.json`. Use `npm run …` for parity with the workspace scripts; do **not** introduce Bun/pnpm lockfiles here.
- **Plugins:** `@sanity/assist`, `sanity-plugin-asset-source-unsplash`, `@sanity/vision`, Presentation Tool.

## Layout

```
/                       npm workspaces root
├── frontend/           Next.js app
│   ├── app/            App Router routes + components
│   │   └── components/ grouped by domain, each with a barrel `index.ts`:
│   │       blocks/ (every pageBuilder block + BlockRenderer/PageBuilder; blocks/gallery/ multi-file),
│   │       layout/, projects/, posts/, motion/, portable-text/, visual-editing/,
│   │       starter/, common/ (SanityImage·ResolvedLink·Date), shader/, icons/
│   ├── sanity/lib/     client, live, queries, api, token, utils, types
│   └── sanity.types.ts generated by TypeGen — DO NOT edit
├── studio/             Sanity Studio
│   └── src/schemaTypes/{documents,objects,singletons}/
├── sanity.schema.json  generated by `sanity schema extract` — DO NOT edit
├── docs/               SHADCN.md (migration log), A11Y.md (a11y rules — read before UI work), TRANSITIONS.md, PHASE0-AUDIT.md (conventions/dep audit + background stub spec)
└── AGENTS.md           "read Next docs from node_modules first"
```

## Commands

Run from repo root unless noted:

- `npm run dev` — runs Next (`:3000`) and Studio (`:3333`) in parallel.
- `npm run lint` — ESLint on frontend.
- `npm run type-check` — `tsc --noEmit` in both workspaces.
- `npm run format` — Prettier (`@sanity/prettier-config`).
- `npm run import-sample-data` — imports `studio/sample-data.tar.gz` into the `production` dataset.
- Frontend build: `npm run build --workspace=frontend` (runs `sanity typegen generate` first via `prebuild`).
- Studio deploy: `npm --workspace=studio run deploy`.

**TypeGen** runs automatically on `predev`/`prebuild`. If `sanity.types.ts` or `sanity.schema.json` drift, regenerate with `npm run sanity:typegen --workspace=frontend` (extracts schema from `studio/`, writes types into `frontend/`).

## Sanity content model

Documents: `page`, `post`, `person`, `project`, `category`. Singleton: `settings` (id `siteSettings`; includes the `builtWith` tech list rendered in the footer). Objects: `callToAction`, `infoSection`, `note`, `scores`, `projectsArchive`, `background`, `button`, `link`, `blockContent`, `blockContentTextOnly` (plus pre-existing `faq`, `stats`, `postsArchive`, etc.). The `page` document has a `pageBuilder` array rendered by `app/components/blocks/PageBuilder.tsx` → `blocks/BlockRenderer.tsx`; every block (and the `page` itself) can carry an optional `background` (none | animated WebGL shader) via the shared `backgroundField` mixin in `studio/src/schemaTypes/objects/shared.ts`. The `page` also has a single-select `archive` field (the shared `archiveField`): when set to an archive block type (`postsArchive` | `projectsArchive` | `authorsArchive`, see `ARCHIVE_BLOCK_TYPES` in `shared.ts`), the page must contain exactly one matching archive block and no other archive blocks (validated on `pageBuilder`), and each archive is unique to one page (async validation on `archiveField`). Archive blocks remain usable freely on non-archive pages.

The `project` document (`title`, `slug`, `excerpt`, `coverImage`, `publishedAt`/`updatedAt`, `website`, `repo`, `tech[]→category`, `featured`, `body`, `ogImage`) mirrors `post` as a routable doc.

Routing (mirror in Studio's Presentation `mainDocuments` + Next routes):
- `/` → `settings`
- `/:slug` → `page`
- `/posts/:slug` → `post`
- projects/posts/authors **listings are normal `page` documents** designated via `page.archive` (carrying the matching `*Archive` block) — there is no standalone `/projects` route. The detail back-link + taxonomy chips resolve the archive page's slug via `archivePageSlugQuery`; chips deep-link with `?tag=`/`?tech=` (filters seeded client-side in `ProjectsList`).
- `/projects/:slug` → `project` detail (metadata section; card→detail View-Transition morph `project-card-${slug}`)

## Queries / data fetching

- All queries live in `frontend/sanity/lib/queries.ts`, wrapped in `defineQuery` so TypeGen can type results.
- Fetch via `sanityFetch` from `@/sanity/lib/live` (RSC). It returns `{data}` — destructure. For `generateStaticParams` and metadata, pass `perspective: 'published'` and `stega: false`.
- The `<SanityLive>` component in `app/layout.tsx` is required for live updates — never remove it.
- Client: `useCdn: true` with stega studioUrl. Server token comes from `SANITY_API_READ_TOKEN` via `sanity/lib/token.ts`.

## Conventions

- Server Components by default. Client components are explicit (`'use client'`) and small (`PageBuilder`, `DraftModeToast`, etc.).
- Visual Editing: wrap editable regions in `data-sanity={dataAttr({id, type, path}).toString()}`. The `PageBuilder` already does this for the array and each block via `pageBuilder[_key=="..."]`.
- Optimistic edits use `useOptimistic` from `next-sanity/hooks` — keep block reconciliation by `_key` (see `PageBuilder.tsx`).
- Components live in `frontend/app/components/`, grouped by domain with a barrel `index.ts` per folder (`blocks/` incl. `blocks/gallery/`, `layout/`, `projects/`, `posts/`, `motion/`, `portable-text/`, `visual-editing/`, `starter/`, `common/`, `shader/`, `icons/`). Import across folders via the barrel (`import {PostCard} from '@/app/components/posts'`); within a folder use relative paths (`./PostCard`). A new pageBuilder block goes in `blocks/`; a multi-file feature gets its own subfolder + barrel.
- Images: use `@/app/components/common` (`SanityImage`, built on `sanity-image`). `next.config.ts` allows `cdn.sanity.io` for `next/image` cases.
- Portable Text: render via `@/app/components/portable-text` (`PortableText`, posts) or `@portabletext/react` directly for short fields. Strip stega before plain-text use (`toPlainText`).
- Styling: Tailwind v4 — colors/tokens are declared in `@theme inline` inside `app/globals.css` (the source of truth; no `tailwind.config.ts`). shadcn components live in `frontend/components/ui/`. Use the `container` utility defined in `globals.css`.
- Path alias `@/*` → `frontend/*`.
- View transitions: React `<ViewTransition>` is enabled (`experimental.viewTransition`). **Always consider transitions when building UI** — see [docs/TRANSITIONS.md](docs/TRANSITIONS.md). App-wide crossfade + directional slides live in `app/components/motion/PageTransition.tsx` (wrapped around `{children}` in `layout.tsx`); tag navigations with `<Link transitionTypes={['nav-forward'|'nav-back']}>`, give cross-route persistent elements a matching `<ViewTransition name>`, and wrap streaming `<Suspense>` in enter/exit `<ViewTransition>`s. Keep these RSC; CSS classes live in the view-transition block of `app/globals.css`.
- TS: strict; the workspace targets `esnext` with `module: preserve`. Don't add `any` to schema-derived types — extend the types in `sanity/lib/types.ts` instead.

## Visual Editing / Draft Mode

- Studio's Presentation Tool points at `SANITY_STUDIO_PREVIEW_URL` (default `http://localhost:3000`), enable route `/api/draft-mode/enable`.
- Draft mode is toggled by `app/api/draft-mode/enable/route.ts` (uses `defineEnableDraftMode`) and disabled by the server action in `app/actions.ts`.
- The `<VisualEditing/>` component only renders when `draftMode().isEnabled` is true.

## Gotchas

- `AGENTS.md` rule: read `node_modules/next/dist/docs/` before doing Next.js work — training data is older than v16.
- Never edit `frontend/sanity.types.ts` or `sanity.schema.json`; rerun TypeGen.
- After adding/changing a schema, re-run TypeGen *before* writing queries that reference new fields, otherwise `defineQuery` results will be typed `unknown`.
- New `pageBuilder` block type needs three changes: schema (`studio/src/schemaTypes/objects/...`), GROQ projection in `getPageQuery`, and a renderer in `app/components/blocks/` registered in `BlockRenderer.Blocks` (+ exported from `blocks/index.ts`).
- New routable document type needs: Presentation `mainDocuments` + `locations` entry (`studio/sanity.config.ts`), Next route, sitemap branch in `app/sitemap.ts`, and `resolveHref` update in `sanity.config.ts`.
- Metadata/static-params fetches must pass `stega: false` to avoid encoded markers leaking into titles and URLs.
- `useCdn: true` + Live: Live still subscribes via the listener; CDN only affects the initial fetch.
- shadcn components live in `frontend/components/ui/` (button, card, dropdown-menu, navigation-menu, sheet, sonner, tooltip, alert, avatar, badge, separator, skeleton). Icon library is Heroicons (configured in `components.json`); lucide is not installed.

## Accessibility

Read **[docs/A11Y.md](docs/A11Y.md) before touching UI** — it's the source of truth for color/contrast tokens, focus rules, ARIA conventions, image alt handling, and the per-PR checklist. Target is WCAG 2.2 AAA where feasible, AA floor. Use the `design:accessibility-review` skill on non-trivial visual changes; run Lighthouse Accessibility ≥95 in both light and dark before merging.

## Priorities (user preferences, applied here)

Performance-first, low CLS, minimal client JS — keep work in RSC, only opt into `'use client'` for hooks or Visual Editing. Target WCAG AAA where feasible — see [docs/A11Y.md](docs/A11Y.md). Avoid heavy deps. Prefer streaming/`<Suspense>` for post lists (already used on `/` and `/posts/[slug]`).
